# 会话绑定业务空间与独立空间管理设计方案

状态：当前实现按 2026-10-12 的会话列表交互修订更新；此前实现及验证记录保留在文末。

修订日期：2026-10-12。

第 1～9 节描述当前产品规则。空间及来源在独立页面管理，空间选择与历史筛选位于会话列表；输入框下方不展示空间信息。

## 1. 目标与核心规则

解决新建会话反复选择来源的问题，同时将业务配置与聊天交互分开。

本方案根据审核意见调整以下交互：

1. 业务空间以及关联来源在独立“业务空间”页面管理，移除会话上方的空间管理与来源选择区。
2. 每个会话绑定一个业务空间，不同会话可以绑定不同空间。业务空间在会话列表处显示和切换。
3. 空间管理页支持编辑关联的业务数据源和知识库。
4. 移除会话列表中的“生效知识库”配置，来源统一在业务空间页面维护。

核心规则：**业务空间统一定义可用来源，会话只绑定空间；新会话复用空间，用户无需重复选择来源。**

本版取消会话临时覆盖来源和“设为此空间默认”操作。业务空间的关联来源即其正式配置，不再区分空间来源与会话来源两套可编辑配置。

## 2. 页面与导航

在主导航增加独立“业务空间”入口，与“智能问数”“业务数据”“知识库”等页面并列。

| 页面 | 职责 |
| --- | --- |
| 智能问数 | 会话列表、空间切换、对应历史消息、提问和回答 |
| 业务空间 | 创建、编辑空间，配置关联数据源和知识库，从空间发起新对话 |
| 业务数据 | 维护数据源本身，包括导入、连接和数据说明 |
| 知识库 | 维护知识库本身，包括文档上传、处理和内容管理 |

业务空间负责关联已存在的资源，不复制数据或文档。编辑关联不会修改或删除原数据源、知识库。

### 2.1 业务空间列表

采用列表或卡片呈现每个空间：

```text
业务空间                                      [新建业务空间]

销售分析
业务数据源 2 个 · 知识库 1 个 · 可用
[编辑]  [新建对话]

产品支持
业务数据源 0 个 · 知识库 3 个 · 可用
[编辑]  [新建对话]
```

展示空间名称、关联资源数量及状态。数量按配置显示；存在不可访问或失效关联时单独提示，避免让数量暗示全部可用。

本次支持创建与编辑，不增加空间删除、共享和成员管理，以免引入已有会话处置及权限模型的新问题。

### 2.2 业务空间编辑

在业务空间页面内打开编辑表单；支持新建和编辑相同的信息：

```text
编辑业务空间

空间名称          [销售分析                         ]

关联业务数据源
[✓] 销售明细
[✓] 客户订单
[ ] 库存数据

关联知识库
[✓] 销售政策
[ ] 产品手册

保存后，此空间内所有会话的后续提问将使用更新后的来源。
                                              [取消] [保存]
```

规则：

- 名称必填；来源可多选，支持仅业务数据源、仅知识库或两者组合。
- 可以保存无来源空间，状态显示“待配置”；此空间内的提问需完成配置后才能执行。
- 资源较多时提供名称搜索，并分别显示已选数量。
- 默认只展示当前用户可访问资源；已有失效关联显示“已失效或无权限”，不展示无权访问资源的敏感详情。
- 已失效关联必须移除或替换后才能保存。不得无提示地清除已有选择。
- 点击保存后统一生效，取消放弃本次编辑。提交失败保留表单及选择，显示具体原因。
- 页面提供“管理业务数据”“管理知识库”跳转入口；返回时保留未提交表单，刷新资源列表。
- 沿用当前项目的用户独立资源权限，空间仅供所属用户配置和使用。

## 3. 会话界面

### 3.1 聊天区

会话上方移除以下内容：

- 空间选择器、新建空间和“设为此空间默认”按钮。
- 当前来源摘要及业务数据源复选框。
- 来源配置说明。

业务空间选择器放在会话列表顶部，输入框下方不展示空间名称或配置入口：

```text
会话列表                         聊天区
业务空间
[销售分析                         ▾]
[新建对话]
该空间的历史会话列表…             [输入问题：华东区上个月销售额下降的主要原因是什么？]
                                 [模型选择]                         [发送]
```

选择器只负责切换当前业务空间，不提供来源编辑。需要创建或编辑空间及其数据源、知识库时，从独立业务空间页面管理。答案中的来源引用、查询证据继续保留，便于核对实际回答依据。

### 3.2 会话列表

移除“生效知识库”及所有知识库复选框。历史列表显示会话名称；空间归属由顶部选择器明确，不展示知识库和数据源明细。

会话列表顶部显示业务空间选择器。切换空间后，历史列表只展示该空间绑定的会话；若该空间有历史会话，打开其中最近更新的一条并恢复聊天记录。若没有历史会话，则进入绑定该空间的空白草稿，不创建服务端会话记录。切换具体历史会话时恢复该会话的空间及消息，并同步更新选择器。

保留新建、重命名、置顶、删除会话等现有操作。切换空间只筛选历史并选择目标会话，不修改已有会话绑定。

## 4. 新会话与绑定规则

| 场景 | 目标行为 |
| --- | --- |
| 在已有会话点击“新建对话” | 草稿沿用当前选择的业务空间，清空聊天记录 |
| 从业务空间页面点击“新建对话” | 进入聊天页，新草稿预绑定该空间 |
| 在会话列表切换业务空间 | 展示目标空间的历史；存在历史时打开最近更新的会话，无历史时显示该空间的新草稿 |
| 当前选择空间后点击“新建对话” | 新草稿自动绑定当前选择的业务空间 |
| 第一次进入且没有当前会话 | 优先使用该用户上次使用且仍可访问的空间；否则使用默认空间；均不可用时要求选择空间 |
| 打开已有历史会话 | 使用该会话保存的空间绑定，不受上次使用空间影响 |
| 已有会话需要使用其他空间 | 通过新建对话选择目标空间，不改变原会话绑定 |
| 空间重命名 | 会话列表选择器显示新名称，原消息保持不变 |

首条消息提交时，服务端将草稿选择的空间写入会话并校验归属。已有会话的空间绑定不可通过聊天请求或普通会话更新修改，防止历史上下文被混入其他业务空间。

只记住用户使用的空间，不记住另一套会话级来源选择。不同用户的空间记忆相互隔离，登录切换不能继承其他账号状态。

## 5. 空间配置变更的生效方式

采用“会话固定绑定空间，后续提问读取空间最新配置”的方式。

这样在管理页更换知识库或业务数据源后，空间内已有会话也能使用新配置，无需逐个会话重新绑定；避免管理页与会话实际使用范围不一致。

具体规则：

1. 每次提问由服务端根据会话的 `workspace_id` 读取空间最新来源并校验权限；客户端不再提交可覆盖空间配置的来源集合。
2. 一次执行开始后固定本次有效来源。执行中修改空间配置，从下一次提问生效，不改变正在执行的请求。
3. 为每次执行记录空间标识、配置版本及实际使用的来源集合；历史回答的引用和证据保持当时记录，不因空间更新被改写。
4. 打开会话或下一次提问前发现配置版本变化，在聊天消息区轻量提示“业务空间配置已更新，后续提问将使用最新来源”。不增加每次确认弹窗。
5. 配置范围变化后，模型上下文不能把旧回答当作新范围的业务证据。仅使用最近一次配置版本变化后的业务问答上下文；旧消息仍在界面展示，需要查询新范围时重新获取证据。
6. 常问问题按最新有效来源集合重新加载；旧范围的统计记录保留，不与新范围混用。

已实施的生效规则：空间修改会影响所有绑定会话的后续提问。编辑页需明确说明这一影响。

## 6. 异常与原问题恢复

| 状态 | 用户反馈 | 恢复路径 |
| --- | --- | --- |
| 草稿未绑定空间 | 请先选择业务空间 | 在会话列表选择已有空间；没有空间时进入管理页创建 |
| 空间未关联来源 | 当前业务空间尚未配置业务数据源或知识库 | 进入该空间编辑页配置 |
| 空间不存在或不可访问 | 当前会话绑定的业务空间不可用 | 阻止查询；在可用空间新建对话，不自动替换原绑定 |
| 关联来源失效或无权限 | 当前空间存在不可用来源，请检查配置 | 管理页移除或替换失效关联后继续 |
| 来源连接异常 | 业务数据源暂时无法连接 | 重试；需要维护时进入业务数据管理页 |
| 检索无结果 | 当前空间未找到相关资料 | 查看空间配置或补充资料，不自动扩大范围 |

存在失效关联时阻止该次业务执行，避免只查询剩余来源而让用户误以为结果完整。检索无结果与配置缺失分别反馈。

用户跳转配置页面时，保留原会话、输入草稿或待重试问题。通过“返回对话”回到发起位置，刷新空间配置后由用户点击“继续提问”，不自动重复发送。切换其他会话时，不把待重试问题带到新会话。

## 7. 数据与接口调整建议

本节说明本次实施的数据与接口规则，迁移版本为 `0006_workspace_binding`。

| 对象 | 职责与本次变化 |
| --- | --- |
| 业务空间 | 保存名称、关联知识库和数据源，以及递增配置版本 |
| 会话 | 持久化唯一空间绑定；来源集合不再作为可编辑的会话配置 |
| 执行记录 | 保存本次空间标识、配置版本、实际来源集合，支撑历史核对及上下文隔离 |
| 前端草稿 | 保存当前预选空间及输入内容，跨管理页跳转可恢复 |

接口方向：

- 沿用空间列表、创建、编辑接口，为管理页补充配置版本和可用状态。
- 创建会话明确传递空间标识；普通会话更新仅允许标题、置顶等操作，不开放来源覆盖或空间迁移。
- 聊天执行统一由服务端解析会话空间和有效来源。已有会话以服务端保存的绑定为准。
- 移除前端会话级来源提交。旧调用方若仍提交来源覆盖，明确返回错误，避免静默忽略导致误解。
- 常问列表按所属空间解析当前有效范围，并复用现有来源集合统计口径。
- 空间、会话、来源和执行记录均校验当前用户归属；配置版本不代替权限校验。

### 历史数据兼容

现有迁移已把历史会话归入默认空间，但上一版可能保存过不同的会话临时来源。本次升级不能将这些不同范围无提示地合并成一个空间。

已实施迁移策略：

1. 保留所有历史消息及已保存的来源引用。
2. 会话来源集合与所属空间配置一致时保留绑定。
3. 不一致时，按“用户 + 原空间 + 排序去重后的来源集合”归组，生成明确命名的兼容空间并绑定相应会话，例如“默认业务空间 · 历史范围 1”。同一范围只生成一个兼容空间。
4. 不将失效来源替换为其他资源；兼容空间标记为待检查，用户在管理页修复。
5. 迁移应可重复执行、不重复生成空间；升级前备份数据库，并在空间管理页提示历史范围已保留。

## 8. 实施范围与顺序

1. 建立独立业务空间管理页，完成创建、编辑、来源关联和“新建对话”入口。
2. 清理聊天区上方及会话列表的来源配置，在会话列表增加业务空间选择器并按空间筛选历史。
3. 调整会话绑定与服务端范围解析，接入空间版本、执行范围记录及配置变化后的上下文隔离。
4. 迁移上一版会话临时范围，完善配置跳转返回、原问题保留及常问范围刷新。
5. 验证历史会话、跨空间切换、权限、流式回答、停止生成和来源引用等功能。

本次不包含自动路由、业务口径澄清、组织共享空间、成员权限申请、独立助手管理或空间删除。智能选择后续也只能在绑定空间授权范围内进行。

## 9. 审核重点与验收场景

验收关注点：

- 已有会话固定绑定空间；需要其他空间时新建对话。
- 空间配置修改对所有绑定会话的后续提问生效，历史回答保持原样。
- 会话列表切换空间后只展示该空间的历史；新对话沿用当前选择空间。
- 上一版临时来源差异通过兼容空间保留，避免迁移后改变业务范围。

验收场景：

1. 业务空间可在独立页面创建和编辑，关联来源保存后重新打开仍一致。
2. 会话上方没有空间管理及数据源选择；会话列表没有“生效知识库”及相关复选框。
3. 输入框下方不显示业务空间信息；会话列表显示当前空间选择器，已有会话不能改绑。
4. 从空间页发起新对话自动绑定该空间；从会话列表新建对话自动绑定当前选择空间。
5. 两个会话绑定不同空间，切换空间后历史列表、当前会话和实际查询范围对应正确。
6. 修改空间来源后，已有会话下一次提问使用新配置；进行中的执行及历史回答不变。
7. 配置变化后不把旧范围答案当作新范围证据；常问列表按新范围刷新。
8. 缺少配置时保留问题，管理页配置后返回可继续提问，且不自动重复发送。
9. 跨用户访问、失效来源和不可用空间不会导致越权、自动回退或静默扩大范围。
10. 历史会话来源差异迁移后可在对应空间查到，消息及引用无丢失。

## 10. 上一版实施记录（历史，不代表本次方案已实施）

- 新增用户独立业务空间，可创建空间、切换空间、将当前范围明确保存为空间默认值。复用现有助手与模型配置。
- 会话持久化 `workspace_id`、`kb_ids`、`source_ids`。选择来源后即保存当前会话范围，新会话由服务端继承空间默认值。
- 空间切换进入空白草稿，历史会话按空间筛选。刷新或重新打开会话时恢复其范围。
- 来源摘要持续展示在聊天区；资源管理返回后刷新可用来源，移除失效选择并提示。常问功能沿用实际来源集合，随范围更新。
- 空范围的业务空间提问在调用模型前拦截，保留原问题；选好来源后点击“继续提问”。请求失败、流式错误或部分失败同样提供原问题重试入口。
- 服务端在创建会话、保存配置及执行查询时检查资源归属；读取历史会话后由客户端按最新可用资源过滤，不自动扩大范围。
- 数据迁移 `0005_resource_scope` 为已有用户创建空默认空间并归入历史会话，保留原知识库选择。历史数据源未持久化，无法可靠恢复，不猜测关联。

当前空间仅供所属用户管理和使用，未引入跨用户共享、组织默认配置、审批/申请权限流程或独立助手管理。公司、环境等业务边界通过空间划分与来源名称表达，尚无独立结构化字段。自动路由、业务口径澄清属于第三阶段。

连接异常和检索无结果继续由现有执行链路反馈；本次补充错误后的原问题恢复入口，未增加连接诊断页面。具体来源引用沿用现有答案证据组件。

本地升级前备份数据库，执行 `backend/venv/bin/python -m alembic upgrade head`（工作目录为 `backend`），应用要求迁移版本为 `0005_resource_scope`。

## 12. 修订版实施与验证记录（2026-10-12）

### 已实施
