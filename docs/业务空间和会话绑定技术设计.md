# 业务空间和会话绑定技术设计

更新：2026-10-15。本文档说明多数据域隔离中枢——“业务空间（Business Workspace）”与“对话会话（Conversation Session）”绑定机制的技术架构、版本控制演进、并发冲突处理及关联生命周期控制。

## 1. 业务背景与设计目标

在复杂的企业经营分析场景中，不同分析场景所依赖的数据集合不同（例如“华东销售集”、“财务核算库”、“供应链库存表”）。
- **空间级数据域隔离**：通过“业务空间”，将一组特定的数据源（`source_ids`）聚合为一个逻辑业务域，避免大模型在一个超庞大、充满同名同义歧义的全量库中胡乱选择表。
- **会话绑定与上下文延续**：用户在特定业务空间下开启的对话（Session），其内部所有的 Agent 分析推理、SQL 执行、指标查询，均被严格限制在该空间绑定的数据源范围内。
- **数据域版本感知（Scope Versioning）**：当管理员向业务空间增加或剔除数据源时，该空间的版本号单调自增。会话和每条消息记录关联当时的数据范围版本（`scope_version`），可精准识别数据环境漂移，避免模型复用失效的旧表结构知识。
- **任务安全与级联保护**：当会话关联的 Agent 任务仍在后台运行或暂停等待时，禁止删除会话，杜绝产生孤儿运行流。

## 2. 总体架构与实体关系

```text
       ┌────────────────────────┐
       │     User (用户主体)    │
       └───────────┬────────────┘
                   │ 1:N
       ┌───────────▼────────────┐
       │   BusinessWorkspace    │ ◄─── 管理一组数据源 (source_ids)
       │ (id, name, version...) │      状态: ready / empty / invalid
       └───────────┬────────────┘
                   │ 1:N (弱关联/置空保护)
       ┌───────────▼────────────┐
       │      Conversation      │ ◄─── 绑定 workspace_id 与 scope_version
       │ (id, title, pinned...) │
       └───────────┬────────────┘
                   │ 1:N (强关联级联删除)
       ┌───────────▼────────────┐
       │        Message         │ ◄─── 记录每轮对话内容与图表工具结果
       │ (id, content, tools...)│
       └────────────────────────┘
```

## 3. 数据模型设计

由 `app/models/conversation.py` 定义核心表结构：

### 3.1 业务空间表：business_workspaces

| 字段名 | 类型 | 说明 | 约束 |
| :--- | :--- | :--- | :--- |
| `id` | `VARCHAR(36)` | 空间主键 UUID | PK |
| `user_id` | `VARCHAR(36)` | 所属用户 ID | FK -> `users.id` (CASCADE), 索引 |
| `version` | `INTEGER` | 空间配置版本（涉及数据源变更时递增） | 默认 1 |
| `name` | `VARCHAR(100)` | 业务空间展示名称 | NOT NULL |
| `source_ids` | `TEXT` | 绑定的数据源 ID 列表（JSON 序列化存储） | 默认 `'[]'` |

### 3.2 对话会话表：conversations

| 字段名 | 类型 | 说明 | 约束 |
| :--- | :--- | :--- | :--- |
| `id` | `VARCHAR(36)` | 会话主键 UUID | PK |
| `user_id` | `VARCHAR(36)` | 所属用户 ID | FK -> `users.id` (CASCADE), 索引 |
| `workspace_id` | `VARCHAR(36)` | 绑定的业务空间 ID | 可空，FK -> `business_workspaces.id` (SET NULL) |
| `title` | `VARCHAR(200)` | 会话标题（支持自动生成或手动修改） | 默认 `'新建对话'` |
| `model` | `VARCHAR(50)` | 会话指定的基座模型标识 | 默认空字符串（走全局默认） |
| `scope_version` | `INTEGER` | 会话建立/最后同步时对应空间的数据版本号 | 默认 0 |
| `is_pinned` | `BOOLEAN` | 是否置顶显示 | 默认 False |
| `created_at` | `DATETIME` | 创建时间 (UTC) | 默认当前时间 |
| `updated_at` | `DATETIME` | 更新时间 (UTC) | 自动更新触发 |

### 3.3 消息明细表：messages

- `conversation_id`: 外键关联 `conversations.id`，级联删除（`cascade="all, delete-orphan"`）。
- `scope_version`: 记录该轮生成时的数据环境版本。
- `tool_calls`: 存储图表配置、SQL 结果、中间执行卡片的 JSON 证据。

## 4. 关键机制与业务规则

### 4.1 自动初始化与确定性 UUID

为保证每位新用户首次登录即具备开箱即用的体验，`GET /workspaces` 采用惰性保障策略：
- 若用户未创建任何空间，系统使用命名空间 URL 确定性生成其专属默认业务空间：
  ```python
  workspace_id = str(uuid.uuid5(uuid.NAMESPACE_URL, f'rag-workspace:{user.id}'))
  ```
- 并发初始化时通过数据库唯一约束冲突（`IntegrityError`）回滚并重新获取，确保并发安全。

### 4.2 空间健康状态诊断（Status Computation）

每次拉取业务空间时，服务端动态对比空间内保存的 `source_ids` 与系统现有真实 `DataSource`：
- `unavailable_source_ids = source_ids - existing_sources`
- 状态判定：
  - `invalid`：存在已被物理删除的无效数据源 ID（提示用户“包含已失效数据源，请重新编辑”）。
  - `empty`：尚未绑定任何数据源（不能开启问数分析）。
  - `ready`：所有绑定的数据源均可用，分析 Agent 可正常接入。

### 4.3 乐观锁与数据源版本演进

在 `PUT /workspaces/{id}` 更新空间时：
1. 校验请求体中的 `version` 是否与数据库一致；若不一致，返回 HTTP 409（“业务空间已被更新，请刷新配置后重新编辑”）。
2. 计算新旧 `source_ids` 是否发生变化：
   ```python
   changed = sorted(set(payload.source_ids)) != sorted(set(json.loads(workspace.source_ids)))
   new_version = workspace.version + int(changed)
   ```
3. 仅当数据源增减时，版本号自增；纯粹修改名称时不递增版本号，平滑兼容现有会话。

### 4.4 会话绑定与删除拦截（Active Run Guard）

- **绑定校验**：在 `POST /sessions` 时，强制通过 `get_workspace(db, user_id, workspace_id)` 校验空间归属权与健康状态，防止越权绑定他人空间。
- **活跃任务拦截**：在 `DELETE /sessions/{id}` 时，执行严格任务检查：
  ```python
  active_run = await db.scalar(select(AgentRun.id).where(
      AgentRun.conversation_id == session_id,
      AgentRun.status.in_(['queued', 'running', 'cancel_requested', 'paused'])).limit(1))
  if active_run:
      raise HTTPException(409, "会话仍有 Agent 任务运行，请先停止任务后再删除")
  ```
  避免物理删除会话导致异步 Worker 写入脏数据或发生死锁。

## 5. API 契约与使用范式

| 方法 | 路径 | 描述 |
| :--- | :--- | :--- |
| `GET` | `/workspaces` | 查询当前用户所有业务空间列表及可用性状态 |
| `POST` | `/workspaces` | 创建新业务空间（输入名称、数据源 ID 集合） |
| `PUT` | `/workspaces/{id}` | 更新业务空间配置（支持乐观锁校验） |
| `GET` | `/sessions` | 查询会话列表（置顶优先，其次按 `updated_at` 倒序） |
| `POST` | `/sessions` | 新建对话（绑定 `workspace_id`, 指定模型, 初始标题） |
| `GET` | `/sessions/{id}/messages` | 加载指定会话的全部历史消息与工具图表快照 |
| `DELETE` | `/sessions/{id}` | 校验并删除会话（带活跃任务保护） |
