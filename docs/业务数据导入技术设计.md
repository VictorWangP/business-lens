# 业务数据导入技术设计

更新：2026-10-15。本文档说明智能问数系统针对用户上传的表格文件（CSV、Excel）以及外部数据库连接的“业务数据导入与分析引擎适配”技术架构、文件安全审查、强类型推断机制与查询隔离保护。

## 1. 业务需求与技术选型

业务数据导入模块负责将分散在各部门的业务流水（如销售台账、客户工单、财务明细）转换为大模型能够进行精确 SQL 统计分析的高性能结构化数据源。

| 数据形态 | 接入方式 | 底层分析引擎 | 优势与设计重点 |
| :--- | :--- | :--- | :--- |
| **本地文件 (CSV / Excel)** | 文件上传解析并物化 | 嵌入式 **DuckDB** | 零外部运维依赖、内存与列式存储结合、百毫秒级 OLAP 聚合、强类型落盘 |
| **外部数据库 (PostgreSQL)** | 外部连接串授权接入 | PostgreSQL 只读连接池 | 适于生产环境实时数仓，采用白名单视图与凭据对称加密 |

## 2. 总体导入与物化流程

```text
[ 用户上传 CSV 或 XLSX 文件 ]
        │
        ▼ (POST /data-sources/import)
[ 1. 文件流式检查与安全风控 ]
        │ 校验上传大小 (<= MAX_UPLOAD_BYTES, 默认 50MB)
        │ 针对 XLSX: 检查 Zip 解压后体积 (<= 200MB, 防 Zip 炸弹)
        │ 校验行数 (<= 100,000) 与列数 (<= 200)
        │ 阻断 Excel 公式 ('f') 或错误单元格 ('e')，强制只读数据值
        ▼
[ 2. 自动化强类型推断 (Type Inference) ]
        │ 逐列扫描数据样本，严格推断为:
        │ DECIMAL(38, scale) / BOOLEAN / DATE / TIMESTAMP / VARCHAR
        ▼
[ 3. 物化落盘至 DuckDB ]
        │ 写入用户隔离目录: STORAGE_DIR/users/{user_id}/data_sources/{source_id}/business.duckdb
        │ 在 DuckDB 中建表并映射为标准视图: CREATE VIEW dataset AS ...
        ▼
[ 4. 凭证加密与元数据登记 ]
        │ 对连接串 "duckdb:///path..." 执行对称加密 (Fernet/AES)
        │ 写入 data_sources 表 (kind='duckdb', allowed_views=['dataset'])
        ▼
[ 返回数据集规格 (列名、类型、行数、Sheet 列表) ]
```

## 3. 文件处理与类型推断算法（app/application/tabular.py）

### 3.1 格式适配与解压安全

- **CSV 格式**：
  - 强制采用 `utf-8-sig` 解码，兼容 Windows Excel 导出的带 BOM 文件。
  - 使用 `csv.Sniffer` 动态嗅探 `,`、`;` 或 `\t` 分隔符。
- **Excel (.xlsx) 格式**：
  - **防 Zip 炸弹防护**：在完整加载前，先遍历 ZipArchive 内各流的解压总和，若超过 200MB 立即终止抛出异常。
  - **只读只值解析**：使用 `openpyxl(read_only=True, data_only=False)` 检查单元格类型。若存在 `f`（公式单元格）或 `e`（错误值），提示“包含公式或错误单元格，请先复制并粘贴为值后导入”，避免未计算公式造成数据歧义。
  - **多 Sheet 识别**：若未指定 Sheet，默认导入第一张工作表，同时返回全部 `sheets` 供前端选择切换。

### 3.2 严密的列类型自动推断规则

为防止所有数值均退化为字符串导致后续模型生成的 SQL 无法进行 `SUM()`、`AVG()` 聚合，系统在导入时执行高精度推断：
1. **空值兼容**：空文本与 `None` 写入 NULL；字面文本 `"NULL"` 保留为文本。全空列使用 VARCHAR。
2. **整数与小数（DECIMAL）**：数值文本匹配 `^[+-]?\d+(?:\.\d+)?$`，保留实际小数位数，整数使用 scale=0；整数位数与小数位数合计不超过 38。`0012` 等前导零编码保留为文本，超出精度范围的值也回退为文本。
3. **布尔（BOOLEAN）**：列中所有非空值均为原生布尔值时使用 BOOLEAN。
4. **日期（DATE）**：严格匹配 `YYYY-MM-DD` 的有效日期文本或原生 `datetime.date` 对象。
5. **时间戳（TIMESTAMP）**：日期兼容列中含原生 `datetime.datetime` 时使用 TIMESTAMP；普通时间戳字符串不会单独触发推断。
6. **回退文本（VARCHAR）**：包含混合字母、不可解析格式或长描述时，保守回退为文本。

## 4. 数据模型与安全设计

### 4.1 数据源主表：data_sources

| 字段名 | 类型 | 说明 | 约束 |
| :--- | :--- | :--- | :--- |
| `id` | `VARCHAR(36)` | 数据源主键 UUID | PK |
| `user_id` | `VARCHAR(36)` | 所属用户 ID | FK -> `users.id`, 索引 |
| `name` | `VARCHAR(100)` | 业务显示名称 | NOT NULL |
| `kind` | `VARCHAR(30)` | 类型：`duckdb`、`sqlite` 或 `postgres` | NOT NULL |
| `connection_secret`| `TEXT` | 加密后的连接串（不可明文泄露） | NOT NULL |
| `schema_name` | `VARCHAR(63)` | 业务模式名（DuckDB 为 `main`，PG 为业务 schema） | NOT NULL |
| `allowed_views` | `JSON` | 允许查询的安全视图名列表 | NOT NULL |
| `description` | `TEXT` | 包含文件名、导入行数、Sheet 的描述 | 默认空字符串 |

### 4.2 凭据加密与敏感信息隔离

- 数据库连接串（包含密码或本地绝对磁盘路径）在存入数据库前，通过 `app/infrastructure/credentials.py` 执行强对称加密。
- 前端和任何非底层查询执行器在任何情况下均无法通过 API 获取明文 `connection_secret`。对外暴露的接口仅下发脱敏后的元数据（`id`, `name`, `kind`, `allowed_views`, `description`）。

### 4.3 查询安全沙箱（SQL Policy）

当大模型或测试接口需要对已导入的数据源执行 SQL 时：
- **标识符校验**：库名、模式名、表名必须符合正则 `^[a-zA-Z_][a-zA-Z0-9_]*$`，禁止包含 `pg_`、`information_schema` 等系统级命名空间。
- **AST 只读校验**：在 `app/analytics/sql_policy.py` 中解析 SQL 语法树，严格仅允许只读 `SELECT` 语句，全面禁止 `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `CREATE` 等写操作与 DDL。
- **行数保护**：每次查询强行附加行数上限截断（最大返回 200 行，模型可见预览 20 行），防止百万行结果导致 API 连接打满或内存溢出。
