# 对话开场白技术设计

更新：2026-10-15。本文档说明智能问数系统中“对话开场白（Welcome Setting）”与“引导问题推荐（Starter Questions）”的技术架构、配置存储、动态呈现机制及与常问问题的联动策略。

## 1. 业务价值与交互定位

智能问数助手面对初次使用或进入新业务空间的用户时，空白的对话框往往会导致用户“不知道能问什么”或“不知道怎么问出准确的问题”。
- **拟人化破冰与角色设定**：通过可定制的助理称谓、问候语及职责描述，清晰告知用户当前助手的能力边界（如销售核算、供应链指标、财务台账）。
- **示范引导与一键探索**：提供多张引导问题胶囊卡片，点击即可发起提问，帮助用户快速感知系统的数据分析能力。
- **动态联动常问问题**：除静态预设问题外，与业务空间的“高频常问问题”机制融合，形成自学习、自演进的开场体验。

## 2. 总体架构与数据流

```text
[ 用户进入全新/空白会话 ]
           │
           ▼ (前端检测: messages.length === 0 && welcome_setting.is_enabled)
[ 请求 GET /settings/app-config ]
           │
           ├─ 读取 welcome_setting: { greeting, assistant_name, description, questions }
           └─ 读取 frequent_questions 模块推荐的高频真实提问
           ▼
[ 前端渲染开场白组件 (Thread.tsx / WelcomeCard) ]
           │
           ├─ 顶部问候语与机器人徽标 (如 "我是经管之星·AI问数助手")
           ├─ 职责功能介绍文本
           └─ 引导问题列表 (静态配置项 + 动态常问词条)
           ▼
[ 用户点击任一引导问题 ]
           │
           ├─ 自动填入消息输入框并立即触发 Agent 任务流
           └─ 产生首条用户消息，开场白平滑淡出，进入正式问答流
```

## 3. 数据模型与配置管理

开场白配置归属于系统级应用配置模型 `app/models/config.py`，并在 `app/schemas/config.py` 中定义其模式：

### 3.1 实体映射：app_configs 表

每个用户在系统内拥有隔离的配置键值记录：
- `user_id`: 用户 ID。
- `config_key`: 标识为 `'welcome_setting'`。
- `is_enabled`: 是否开启开场白功能（布尔值）。
- `config_value`: JSON 文本，序列化保存各项文案与问题列表。

### 3.2 配置 Schema 定义（WelcomeConfig）

```python
class WelcomeConfig(BaseModel):
    is_enabled: bool = True                        # 是否启用开场白引导
    greeting: str = "你好"                         # 顶部问候语
    assistant_name: str = "我是经管之星·AI问数助手"   # 智能助理显示名称
    description: str = (                          # 能力与职责说明
        "欢迎使用智能AI问数，您可以向我咨询经营数据、报表分析相关问题。"
    )
    questions: list[str] = [                      # 静态预设引导问题列表
        "查询最近30天各区域销售总额排名",
        "分析退款率最高的五款商品及原因",
        "对比本季度与上季度的净利润增长走势"
    ]
```

## 4. 前端渲染与状态控制

在 `frontend/src/components/chat/Thread.tsx` 中执行以下状态机判定：

1. **空白会话识别（Empty Session Guard）**：
   ```typescript
   const isInitialEmpty = messages.length === 0;
   const enableWelcome = configs?.welcome_setting?.is_enabled ?? true;
   ```
   只有在 `isInitialEmpty && enableWelcome` 成立时，中央主视窗才挂载开场白容器。
2. **多源问题合并（Source Merging）**：
   - 提取 `configs.welcome_setting.questions` 中的精选模版。
   - 若当前业务空间绑定了数据源，通过 Hook 并行拉取 `frequent_service` 返回的 `top_frequent_questions`。
   - 去重后并排呈现，并标记“推荐”或“常问”徽标。
3. **首问平滑过渡（Seamless Transition）**：
   - 用户点击卡片后，调用 `sendMessage(question)`。
   - 消息状态更新（`messages.length > 0`），开场白卡片通过 CSS 渐隐过渡卸载，避免屏幕闪烁，平滑切换为聊天瀑布流。

## 5. 配置接口与安全校验

- **获取配置**：`GET /settings/app-config`
  - 返回包括 `welcome_setting` 在内的 6 大核心卡片配置，字段默认兜底，防止前端渲染遇到 `null` 崩溃。
- **更新配置**：`PUT /settings/app-config`
  - 请求载荷：
    ```json
    {
      "key": "welcome_setting",
      "is_enabled": true,
      "config": {
        "greeting": "您好，决策者",
        "assistant_name": "财务经营分析助理",
        "description": "已连接2026年企业ERP与销售台账，支持复杂交叉分析与图表生成。",
        "questions": ["查看三季度华东大区销售额", "导出本月退货率超标清单"]
      }
    }
    ```
  - **输入校验规则**：
    - `greeting`: 长度 1~50 字符。
    - `assistant_name`: 长度 1~50 字符。
    - `description`: 长度 0~500 字符。
    - `questions`: 最多允许配置 10 条引导问题，每条问题长度限制在 100 字符以内，系统自动过滤纯空白字符。
