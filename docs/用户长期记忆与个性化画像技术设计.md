# 用户长期记忆与个性化画像技术设计

更新：2026-10-15。本文档说明智能问数系统中的“用户长期记忆与个性化画像（User Memory & Personalization Profile）”技术架构、多维画像模型、置信度动态更新演进，以及与大模型前缀缓存（Prompt Caching）协同注入的工程机制。

## 1. 业务目标与价值定位

企业中的不同使用者（如“区域销售总监”、“财务分析师”、“供应链调度员”）在关注的数据口径、偏好的呈现格式及业务背景上存在巨大差异。
- **跨会话持久记忆**：打破单会话的生命周期限制，在跨越不同天数与不同会话时，系统持续保留并演进对用户特定偏好的记忆。
- **自适应个性化问答**：根据用户的画像特征，自适应定制回答侧重点（例如为财务总监主动突出利润与毛利率，为销售主管默认筛选其管辖大区）。
- **零破坏大模型前缀缓存（Cache-Friendly Injection）**：以非破坏性增量环境消息的方式按需注入，绝不改写旧对话历史，保证大模型供应商的 KV Cache 命中率最大化。

## 2. 总体架构与记忆流水线

```text
[ 用户问答交互 (多轮对话) ]
            │
            ├─ 提取阶段 (异步提取或显式配置)
            ▼
[ 1. 用户画像持久化模型 (user_profiles) ]
   ├─ 四维分类: preference, role, habit, skill
   ├─ 关键键值: { key: "primary_region", value: "华东大区" }
   └─ 置信度加权: confidence (0.0 ~ 1.0)
            │
            ▼
[ 2. 新会话启动与运行期加载 (AgentExecutor) ]
   ├─ 读取当前用户高置信度 (confidence >= 0.7) 画像列表
   ├─ 比较 Checkpoint 中的上一次环境快照 (Environment Snapshot)
   │    ├─ 若环境无变化 ──> 不追加任何消息，维持历史前缀绝对连续 (Cache Hit)
   │    └─ 若画像有更新 ──> 在当前新问题前追加一条增量环境变更系统消息
   ▼
[ 3. 大模型推理执行 ]
   模型感知用户角色、输出风格偏好与关注口径，生成专属个性化回答
```

## 3. 数据模型设计（app/models/memory.py）

用户记忆以关系型实体结构沉淀于 `user_profiles` 表：

### 3.1 实体模型：user_profiles

| 字段名 | 类型 | 说明 | 约束 |
| :--- | :--- | :--- | :--- |
| `id` | `VARCHAR(36)` | 记忆项主键 UUID | PK |
| `user_id` | `VARCHAR(36)` | 所属用户 ID | FK -> `users.id` (CASCADE), 索引 |
| `category` | `VARCHAR(50)` | 画像维度分类 | 默认 `'general'` |
| `key` | `VARCHAR(100)` | 特征属性键（英文标识符） | NOT NULL |
| `value` | `TEXT` | 特征属性值 | NOT NULL |
| `confidence` | `FLOAT` | 记忆置信度（0.0 ~ 1.0） | 默认 1.0 |
| `updated_at` | `DATETIME` | 最近更新/强化时间 (UTC) | 自动更新触发 |

### 3.2 四维画像分类体系（Category Taxonomy）

| 画像分类 (`category`) | 语义范围 | 典型特征示例 | 业务影响 |
| :--- | :--- | :--- | :--- |
| **`role`** | 用户业务角色与岗位职责 | `financial_analyst`（财务分析师）、`regional_director`（大区总监） | 决定默认推荐的业务指标和分析视角 |
| **`preference`** | 表达与呈现偏好 | `presentation_style: "表格优先，结论精简"`、`chart_color: "dark"` | 决定图表类型与回答长短风格 |
| **`habit`** | 业务习惯与常规筛选边界 | `default_region: "华东区"`、`comparison_period: "环比优先"` | 当用户未明确指定范围时提供合理默认值 |
| **`skill`** | 专业技术背景与认知水平 | `sql_proficiency: "expert"`、`stats_level: "advanced"` | 决定回答中是否展示技术执行细节 |

## 4. 前缀缓存友好的环境注入机制（Cache-Friendly Injection）

大模型厂商（如阿里云百炼/DashScope、Anthropic、OpenAI）的前缀缓存计费极其依赖提示词前缀的“字符级严格一致性”。传统做法把每次变化的用户偏好直接硬编码塞入 `System Prompt` 顶部，会导致每次修改偏好甚至换个日期就彻底击穿缓存，大幅增加推理成本和延迟。

本项目采用**环境快照差量增量注入**策略（在 `app/agents/context.py` 中实施）：

1. **固定基底 System Prompt**：通用的分析指令、工具规则保持绝对固定。
2. **环境快照比对（Snapshot Diffing）**：
   ```python
   current_env = {
       "date": date.today().isoformat(),
       "profiles": {p.key: p.value for p in active_profiles}
   }
   ```
   - 会话首次创建提问时，在历史消息顶部追加环境消息。
   - 后续轮次中，比对当前环境与 Checkpoint 中记录的快照哈希；**只要偏好未发生改变，不再追加任何消息，历史前缀保持 100% 连续稳定**。
   - 仅当用户手动变更设置或系统更新了偏好时，才在**当前新提问前追加一条细微的环境更新消息**，绝不改写已存的历史对话轮次。

## 5. 接口与交互契约

### 5.1 获取用户画像记忆

- **路径**：`GET /memory/profiles`
- **权限**：登录用户
- **响应结构（JSON）**：
  ```json
  [
    {
      "id": "mem-101",
      "category": "role",
      "key": "title",
      "value": "华东区销售运营主管",
      "confidence": 1.0,
      "updated_at": "2026-10-15T10:00:00Z"
    },
    {
      "category": "preference",
      "key": "presentation_style",
      "value": "优先输出关键指标卡，表格展示前10项明细",
      "confidence": 0.9,
      "updated_at": "2026-10-15T14:30:00Z"
    }
  ]
  ```

### 5.2 记忆的沉淀与自修正

- **被动提取**：对话任务结束时，轻量 Worker 异步识别用户对话中的明确指令（例如“以后默认帮我看华东区的数据即可”），更新置信度与画像项。
- **主动修正**：用户可在前端“个人偏好设置”界面查阅被系统识别的画像标签，支持一键删除失效标签或修改特定数值，保障用户对其隐私与个人数据的掌控权。
