# 语音转文字和文字转语音技术设计

更新：2026-10-15。本文档阐明智能问数系统中的语音双向交互能力（语音转文字 STT 与文字转语音 TTS）的技术架构、音频流控、模型协议适配及安全限制。

## 1. 架构目标与技术选型

在现代经营分析与数据问答场景中，支持“移动端/免打字语音输入”与“多模态语音朗读播报”可大幅提升业务人员查数效率。

| 交互方向 | 技术定位 | 核心引擎与实现 | 核心考量 |
| :--- | :--- | :--- | :--- |
| **STT（语音转文字）** | 服务端 ASR 模型推理 | 阿里百炼 `qwen3-asr-flash` / Whisper (OpenAI 兼容协议) | 数据分析对数字、专有名词、口径精度极高，需具备强语义与逆文本正则化（ITN）能力 |
| **TTS（文字转语音）** | 客户端/服务端双通道 | 前端标准 Web Speech API（默认）+ 兼容服务端高品质音色（如 Edge TTS / CosyVoice） | 极低时延、免带宽消耗、多平台无缝兼容与本地播放控制 |

## 2. 总体交互流程

```text
【语音输入流程 (STT)】
[ 用户长按/点击录音 ] ──> [ 浏览器 MediaRecorder 采集 PCM/WebM 码流 ]
                                     │ 录音结束，封装为 Blob (audio/webm)
                                     ▼
                      [ POST /audio/transcribe (FormData 上传) ]
                                     │
                      [ 1. 文件合法性与大小检查 (<= 7.5MB / 5分钟) ]
                      [ 2. 凭证解析与回退机制 (STT_API_KEY / 默认模型) ]
                      [ 3. 转 Base64 Data URL 封装 OpenAI 音频消息 ]
                                     │
                      [ 调用百炼/DashScope qwen3-asr-flash ASR (enable_itn=True) ]
                                     │
                      [ 返回转写文本 ] ──> [ 前端自动填入 Chat 输入框并聚焦 ]

【语音播报流程 (TTS)】
[ 大模型生成回答结束 ]
        │
        ▼ (若用户开启 TTS 自动朗读或手动点击消息底部的「朗读」按键)
[ 解析 VoiceTTSConfig (voice_name, speed, is_enabled) ]
        │
        ▼
[ 前端 Web Speech API / SpeechSynthesisUtterance 实例 ]
        │ 剔除 Markdown 标记、代码块、复杂表格数据，保留分析摘要结论
        ▼
[ 本地声卡硬件播放，支持暂停、恢复与语速调节 ]
```

## 3. 语音识别（STT）核心设计

### 3.1 接口定义

- **路径**：`POST /audio/transcribe`
- **认证**：必须通过 Bearer Token 鉴权（`get_current_user`）
- **请求类型**：`multipart/form-data`
  - `file`: 音频二进制文件（支持 `.webm`, `.wav`, `.mp3`, `.m4a`）
- **返回结构（JSON）**：
  ```json
  {
    "text": "查看2026年三季度华东区销售额前五的商品明细"
  }
  ```

### 3.2 凭证智能回退（Credential Fallback）

为简化运维配置并降低多模型密钥管理的门槛，`app/api/audio.py` 实现了多级智能凭证路由：
1. **环境变量优先**：检查是否配置了专用的 `STT_API_KEY` 和 `STT_API_BASE`。
2. **模型配置自动借用**：若未单独配置 STT 密钥，系统自动读取用户在“模型配置（`model_setting`）”中配置的默认对话模型（如已绑定阿里云百炼 DashScope 凭据），自动解密并复用该凭据调用 DashScope 语音识别模型。
3. **错误提示**：若未配置百炼模型且无 STT 密钥，给出明确的用户引导（HTTP 422：“请将默认对话模型配置为百炼模型，或单独配置 STT_API_KEY”）。

### 3.3 音频约束与 ITN 文本规整

在 `app/services/audio_service.py` 中强制执行以下安全保护与质量优化：
- **容量与时长硬限制**：限制上传原始字节不超过 7,500,000 字节（约 7.5MB），单次录音时长不得超过 5 分钟，防止大文件造成 OOM 或服务阻塞。
- **MIME 探测**：校验文件头，严格限定 `audio/*` 媒体类型。
- **ITN 逆文本规整（Inverse Text Normalization）**：在调用 DashScope 请求时传入 `extra_body={'asr_options': {'enable_itn': True}}`。
  - 自动将口语表达“二零二六年九月十五号”规整为“2026年9月15日”。
  - 自动将“三千五百二十万”规整为“3520万”。
  - 极大提高后续 NL2SQL 与意图识别模块的解析精确度。

## 4. 文字转语音（TTS）核心设计

### 4.1 配置模型

在系统设置中心（`app/schemas/config.py`）中维护 `VoiceTTSConfig`：

```python
class VoiceTTSConfig(BaseModel):
    is_enabled: bool = False                      # 全局 TTS 开关
    voice_name: str = "zh-CN-XiaoxiaoNeural"       # 偏好音色名称
    speed: float = 1.0                             # 语速乘数 (0.5 ~ 2.0)
```

### 4.2 前端音频适配器与朗读清洗

前端在 `App.tsx` 与 `components/chat/MessageItem.tsx` 协同处理：
1. **文本预处理（Text Sanitization）**：
   - 过滤 Markdown 图片链接 `![]()`、图表 JSON 块、原始 SQL 查询语句。
   - 提取正文文本段落与关键指标卡结论，避免机械朗读长代码或特殊标点符号。
2. **音色匹配**：
   - 调用 `window.speechSynthesis.getVoices()` 动态枚举客户端安装的自然语音包。
   - 优先匹配配置项中的 `voice_name`（如 `zh-CN-XiaoxiaoNeural` 或系统本地高保真中文女声/男声）。
3. **状态机控制**：
   - 每条消息独立管理 `isSpeaking` 状态。
   - 切换会话、重新提问或点击其他消息的播放按钮时，立刻触发 `window.speechSynthesis.cancel()` 停止旧音频，杜绝多声音重叠。

## 5. 异常处理与性能考量

- **网络超时控制**：ASR 服务端调用严格设置 Client 级超时（如 60s），避免云端挂起造成 Worker 连接泄漏。
- **降噪与收音提醒**：若识别结果为空白（用户误触或纯背景杂音），后端主动返回结构化错误码，前端给予“没有识别到语音内容，请说话后重试”的友好 Toast 提示，不破坏对话流。
