# 会话上下文管理

更新：2026-10-15。本文说明当前项目如何估算模型输入、整理工具结果、摘要早期历史，以及保留近期对话。完整消息和工具证据仍保存在 checkpoint 与应用归档中；上下文整理只改变后续模型请求携带的消息。

## 整体策略

上下文管理分为三个阶段：

1. 每次模型调用前，根据模型输入 usage、稳定前缀和新增消息估算本次输入长度。
2. 输入达到约 100,000 tokens 时，折叠较早轮次的工具正文，保留证据 ID 和重读提示。
3. 折叠后仍达到约 200,000 tokens 时，摘要较早历史，并保留近期消息窗口。

100K 和 200K 是默认工作预算，不是模型的硬容量，也不是性能保证。模型安全容量较小时，触发值会自动向下收紧；Qwen 1M 窗口仍受默认 200K 摘要工作预算控制，避免会话仅因模型能容纳更多内容就持续积累低相关历史。

## 模型容量与输入估算

`app/agents/limits.py` 解析实际模型容量，`ContextManagement` 在每次模型调用前执行输入容量检查：

- 模型设置中的 `context_window`、`max_input_tokens`、`max_output_tokens` 可按部署覆盖自动值。
- 仅官方 DashScope/百炼 MaaS endpoint 上已核实的 Qwen 3.7 Max/Plus/Flash、3.8 Max/Flash 商业型号自动识别为 1,000,000 context、991,808 非思考输入容量。
- 未识别模型默认按 131,072 context 估算；该默认值不代表未知部署的真实规格，应按实际服务配置模型容量。
- 单次模型输出默认最多预留 8,192 tokens，且不会超过模型配置的输出能力。
- `AGENT_CONTEXT_TOKENS` 可设置应用级上下文上限，默认不设置。

容量检查为输出预留空间，并使用以下安全可用预算：

```text
可用输入 = min(模型最大输入, 上下文窗口 - 输出预留)
安全余量 = max(2,048, 上下文窗口 × 10%)
安全历史预算 = 可用输入 - 安全余量 - 固定系统提示与工具定义
```

工具结果清理和摘要阈值分别为 100,000 和 200,000 tokens，并受安全历史预算限制。较小模型的有效阈值为配置值与安全历史预算中的较小值。固定提示和工具定义占用容量；若它们本身超过输入预算，整理历史无法解决问题，系统会直接返回容量错误。

输入估算优先使用运行商返回的 token usage，并记录模型身份、工具定义哈希、消息前缀哈希和实测量。前缀完全匹配时，旧前缀沿用实测量，只估算新增消息；模型、工具定义或前缀发生变化时回退本地估算。上下文被整理后会清除旧估算锚点，等待下一次实测重新建立。缓存读取 token 已包含在输入 usage 中，不会重复累加。

## 工具结果折叠

单个工具返回时就会限制模型可见正文：默认预算约 3,000 tokens；数据库结果预览最多 20 行。更完整的数据保存在受权限保护的证据归档中，可通过结果 ID 分页重读。SQL 最多返回 200 行；被截断的数据不能当作完整集合进行汇总。

当模型输入达到约 100K 时，系统只折叠较早轮次中的旧工具正文，并保留引用 ID、查询 ID、来源 ID 或结果 ID 等可用信息。折叠后的占位内容会提示模型按 ID 重读完整证据。工具调用消息与对应结果配对保留，应用归档中的原始结果不会删除。

折叠保护规则：

- 当前用户问题之后产生的工具结果保留正文，避免正在执行的分析丢失刚查到的证据。
- 最近 8 条工具结果默认保留正文，数量可由 `AGENT_RECENT_TOOL_RESULTS` 调整。
- 最终答案工具消息不会作为普通工具结果折叠。
- 只有占位内容比原结果更短时才替换，避免折叠反而增加上下文长度。

## 早期历史摘要与近期轮次保留

工具结果折叠后，如果输入仍达到约 200K，系统才摘要较早的对话历史。摘要按固定栏目保留用户目标、最新业务条件和口径、已确认事实、完成进度、限制以及证据索引；摘要程序还会复制历史消息和工具 artifact 中可识别的引用 ID，避免依赖模型重新生成这些 ID。

摘要默认保留约 32,000 tokens 的近期原始消息，受模型安全历史预算向下限制。框架按安全消息边界切分，保留近期工具调用及对应结果；若最新实际用户问题落在摘要部分，会将该问题原样带回。早期摘要会继续作为后续上下文的一部分。

摘要是有损整理，不能取代精确证据。金额、行数和引用结论应以归档工具结果及最终答案校验为准。若后续分析需要已经折叠的结果，模型可根据占位符中的引用 ID 调用读取工具恢复内容。

## 前缀缓存

初始系统提示保持固定。日期和用户偏好只在新问题开始时与 checkpoint 中的环境快照比较：首次添加运行环境消息；环境不变时不重复写入；环境变化时在当前问题前追加更新，不改写旧历史。暂停恢复不会重复注入环境消息。这样可让未发生变化的历史前缀保持连续。

摘要或工具正文折叠会从变更位置起改变消息前缀，后续请求需建立新的缓存前缀。系统记录本地前缀哈希与运行商报告的缓存读取量用于诊断；本地前缀一致不代表运行商一定命中缓存，实际命中还取决于运行商支持、缓存策略、路由和有效期。

## 容量溢出恢复

如果运行商明确返回上下文长度错误，系统会强制执行一次工具结果折叠与历史摘要，然后重试模型请求一次。若重试仍因上下文长度失败，会返回明确的容量错误；其他模型错误不进入此恢复路径。恢复成功后的整理消息和模型响应一起写入 checkpoint，避免下一轮又恢复到过长的旧上下文。

如果当前问题或固定提示本身过长，没有可整理的早期历史，系统会报告容量不足，不会静默截断当前问题。checkpoint 和聊天展示归档中的原始消息仍可追溯。

## 配置

| 配置 | 默认值 | 作用 |
| --- | ---: | --- |
| `AGENT_DEFAULT_CONTEXT_TOKENS` | 131,072 | 未识别模型的默认 context 窗口 |
| `AGENT_CONTEXT_TOKENS` | 不设置 | 可选应用级上下文上限 |
| `AGENT_MAX_OUTPUT_TOKENS` | 8,192 | 单次模型输出上限 |
| `AGENT_TOOL_PRUNE_TRIGGER_TOKENS` | 100,000 | 开始折叠较早轮次的旧工具正文 |
| `AGENT_SUMMARY_TRIGGER_TOKENS` | 200,000 | 工具折叠后仍达到该输入量时开始摘要 |
| `AGENT_SUMMARY_KEEP_TOKENS` | 32,000 | 摘要后近期原始消息预算 |
| `AGENT_COMPACTION_BUFFER_RATIO` | 0.1 | 模型 context 的安全余量比例 |
| `AGENT_CONTEXT_SAFETY_TOKENS` | 2,048 | 最低安全余量 |
| `AGENT_TOOL_OUTPUT_TOKENS` | 3,000 | 单个工具的模型可见正文预算 |
| `AGENT_RECENT_TOOL_RESULTS` | 8 | 清理时优先保留的近期工具结果数 |

修改环境配置后需重启 API 和 worker 才会生效。已开始的运行继续使用其创建时的模型容量、阈值和 checkpoint 状态。
