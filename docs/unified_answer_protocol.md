# 统一回答协议与实施方案

日期：2026-10-12。状态：核心实现已完成，待真实模型问答验收。本文件是最终回答、图表展示和延伸问题的统一设计入口。

## 背景与根因

模型既调用查询工具，又在最终自由文本中生成 Mermaid、Python 或图表配置。图表实际上已经通过工具事件送给前端。仅靠提示词和特定关键词过滤无法约束正文；原始历史消息还会把代码再次送回模型。建议问题使用正文定界符拆分，失败被静默忽略；独立前端建议状态容易与消息不同步。独立 worker 不会随 API 的 `--reload` 重载。

## 协议 v1

Agent 的最终返回必须是一个 JSON 对象，不输出 JSON 外的正文。正常流程复用 Agent 的最终一次生成；校验失败只额外调用一次同模型进行格式修复。无需依赖供应商私有的 structured-output API。

```json
{
  "version": 1,
  "sections": [
    {"title": "销售趋势", "summary": "销售收入与毛利…… [查询 Q1]", "query_id": "Q1", "show_table": true}
  ],
  "suggestions": ["延伸问题一", "延伸问题二", "延伸问题三"]
}
```

- `sections`：至少一项；标题不带编号，程序自动生成连续编号。`summary` 支持 Markdown 强调、列表和链接，不允许标题、代码块、HTML 和模型复制的图表配置；数据表格通过关联查询的真实行集生成。
- `query_id`：可选，引用实际执行的查询引用 ID（如 Q1）；`show_table` 默认 false，为 true 时必须指定查询 ID。表格由服务端按真实行集输出，保留空结果和截断提示。
- `code`：section 的可选 `{language, content}` 字段，仅用户明确请求代码/教程时允许。代码不混入 summary。
- `suggestions`：开启时严格为三个非空且不同的问题；关闭时为空数组。同一对象承担生成、事件传输、持久化及历史恢复。
- 图表、指标、知识引用、执行事件继续使用已有通道，模型不得在回答 JSON 中复制图表数组。查询工具向模型返回 `presentation`，说明图表是否备好及实际能力（多序列、单 Y 轴），不谎称浏览器已渲染成功。

## 一个校验出口

使用 Pydantic 检查字段和上限，使用 Markdown AST 检查 summary 的内容类型，检查查询及知识引用授权、代码请求意图和建议数量。JSON 格式不能代替语义正确性；短文本仍可能有错误的业务解释，原有事实与引用约束继续保留。

首次无效时只进行一次格式修复，记录失败类别而不记录原始 provider 响应或凭证。再次失败发出明确错误，不回退展示原始未校验输出。最终通过后产生单个 `answer` SSE 事件，携带协议对象和程序生成的 Markdown `content`；存入现有 `Message.tool_calls.answer`，`Message.content` 保存受控展示文本供复制、朗读、历史上下文及记忆提取使用，不需数据库迁移。

## 前端与兼容

- 继续使用 assistant-ui 的 Text/Markdown、图表工具 UI 和原生建议按钮；不新增通用 UI 框架。
- 编号、表格和显式请求的代码块均由程序组装。前端从最后一条助手消息读取建议，不再独立保存建议 state。
- 新消息优先使用统一协议；暂时接收旧 `chunk`、`suggestions`、`done.suggestions` 事件，兼容已有执行和历史数据。
- 历史自由文本使用 Markdown AST 移除未明确请求的代码块，替代 Python/Mermaid/标题的关键词列表；服务端组装历史上下文时执行同样的代码块边界处理。历史数据不批量改写、不伪造或补填建议；旧绘图教程中的普通文字可能仍保留。
- 完整执行记录、查询 SQL、参数和结果行继续留在默认折叠的分析过程内。

## 验收与运行

覆盖 Mermaid/Python/JSON 代码块、未知查询引用、非法字段、三条建议与开关、一次修复成功及失败、显式代码请求、真实表格转义/截断、SSE/持久化/历史恢复/点击追问、停止及切换会话。已有图表/知识引用测试继续运行。

后端改动部署时同时重启 API 和独立 worker。确认没有运行中的任务后重启 worker；前端重载。实际 provider 的业务准确性与特定模型对协议的遵守率需要真实问答验收，离线测试不能替代这项验证。

## 取舍

正常路径没有第二次 LLM 调用；不合格回答增加一次修复延迟。协议持续不合格时明确失败，避免用空列表把建议失败伪装成完整成功。保留旧事件接收仅用于迁移兼容，后续可统一移除。
