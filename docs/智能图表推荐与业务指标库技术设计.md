# 智能图表推荐与业务指标库技术设计

更新：2026-10-15。本文档说明数据问答系统中的“启发式智能图表自动推荐”、“指标卡片提取”以及“标准化业务指标库（Metric Definition）”的技术设计、数据契约与前后端表现解耦规范。

## 1. 业务目标与设计理念

在传统 AI 问数系统中，大模型常常直接在聊天文本中输出海量的 Markdown 表格、绘图 Python 代码或凌乱的 ECharts 配置，导致移动端排版错乱且用户体验极差。
- **数据与表现彻底解耦**：系统提示词严格禁止模型直接在正文中输出绘图代码或教程，模型只需专注于根据数据特性决策图表意图（`chart_type`）；图表的结构化规格由后端分析引擎统一计算生成，前端原生渲染。
- **启发式图表类型推断与安全降级**：后端根据结果集行数、维度类型（时间列、枚举分类列）与数值分布，智能推导柱状图（Bar）、折线图（Line）、饼图（Pie）；对于不适合画图的数据自动降级。
- **业务指标库标准化（Single Source of Truth）**：通过可配置的业务指标模型，将企业内口径复杂的核心 KPI（如毛利率、复购率、退款率）固化为标准 SQL 模版，模型优先调用标准指标，避免手写自由 SQL 导致的口径偏差。

## 2. 总体架构与数据流

```text
[ 用户问题 (如: "统计近半年各月销售走势") ]
                     │
                     ▼
[ 1. 优先检索业务指标库 (MetricDefinition) ]
   ├─ 命中国标/企标指标 ──> 注入参数执行标准 SQL 模版
   └─ 自由探索性问题 ────> 生成只读 SELECT 聚合查询
                     │
                     ▼
[ 2. 启发式图表与指标推断 (app/analytics/presentation.py) ]
   ├─ 行数 = 1 ────────> 提取为 KPI 核心指标卡 (metrics_from_rows)
   └─ 行数 2 ~ 50 ─────> 推断维度与数值列，生成图表契约 (chart_from_rows)
                         - 时间序列维度 ──> 折线图 (Line)
                         - 离散分类对比 ──> 柱状图 (Bar)
                         - 结构占比分布 ──> 饼图 (Pie，含负数自动降级为柱状图)
                     │
                     ▼ (封装为标准 JSON 证据链)
[ 3. 前端图表原生渲染 (ECharts / ChartCard) ]
   大模型正文仅输出分析洞察与业务结论，图表由前端原生组件独立自适应展示
```

## 3. 标准指标库设计（MetricDefinition）

### 3.1 实体模型

在 `app/models/platform.py` 中持久化：

| 字段名 | 类型 | 说明 | 约束 |
| :--- | :--- | :--- | :--- |
| `id` | `VARCHAR(36)` | 指标主键 UUID | PK |
| `user_id` | `VARCHAR(36)` | 所属用户 ID | FK -> `users.id`, 索引 |
| `source_id` | `VARCHAR(36)` | 关联的数据源 ID | FK -> `data_sources.id` (CASCADE), 索引 |
| `name` | `VARCHAR(100)` | 指标业务名称（如 `月度总销售额`） | NOT NULL |
| `description` | `TEXT` | 指标详细口径描述、分子分母说明 | NOT NULL |
| `sql_template` | `TEXT` | 带参数的参数化 SQL 模版 | NOT NULL |
| `unit` | `VARCHAR(30)` | 业务单位（如 `万元`, `%`, `件`） | 默认空字符串 |

### 3.2 参数化模版与口径固定

指标模版仅支持安全的动态时间切片参数（如 `:start_date`, `:end_date`）：
```sql
SELECT 
    SUM(amount) AS total_sales,
    COUNT(order_no) AS order_count
FROM sales_orders 
WHERE order_date >= :start_date AND order_date < :end_date
  AND status = 'paid';
```
大模型在规划阶段调用 `list_available_resources` 时，系统优先展示当前数据源已注册的业务指标及其说明。模型仅需填入起止时间参数，无需自行猜测表连接关系或过滤条件，从根源杜绝数据幻觉。

## 4. 启发式图表推荐算法实现（app/analytics/presentation.py）

### 4.1 核心推断算法（chart_from_rows）

```python
def chart_from_rows(rows: list[dict], title: str, chart_type: str = 'bar') -> dict | None:
    # 1. 规模保护：超过 50 行不适合单图展示，直接降级为普通表格
    if not rows or len(rows) > 50:
        return None
    
    # 2. 字段类型动态探测
    numeric = [k for k in rows[0] if any(isinstance(r.get(k), (int, float, Decimal)) and not isinstance(r.get(k), bool) for r in rows)]
    categories = [k for k in rows[0] if k not in numeric]
    
    # 3. 维度兼容处理：对于将年份/月份以整型表示的数据集，智能识别为离散时间维度
    if not categories and len(numeric) >= 2:
        dimensions = {'sign_month', 'month', 'year', 'week', 'day', '月份', '年份'}
        categories = [key for key in numeric if key.lower() in dimensions][:1]
        numeric = [key for key in numeric if key not in categories]
        
    if not numeric or not categories:
        return None
        
    x = categories[0]
    kind = chart_type if chart_type in {'bar', 'line', 'pie'} else 'bar'
    
    # 4. 饼图安全性检查：包含负数或总和 <= 0 时，自动降级为柱状图
    if kind == 'pie' and (any(r.get(numeric[0]) is None or r[numeric[0]] < 0 for r in rows) or sum(r[numeric[0]] for r in rows) <= 0):
        kind = 'bar'
        
    return {
        'type': kind,
        'title': title,
        'x_key': x,
        'y_keys': numeric[:2],  # 最多支持双指标对照
        'data': [{x: str(r.get(x, '')), **{k: float(r[k]) if r.get(k) is not None else None for k in numeric[:2]}} for r in rows]
    }
```

### 4.2 单值汇总自动转化为 KPI 卡片（metrics_from_rows）

当 SQL 语句为单行聚合（`len(rows) == 1`）时，自动提取每个数值字段为独立 KPI 卡片，自动拼接指标单位：
```json
[
  {"label": "total_sales", "value": "1285.5 万元"},
  {"label": "order_count", "value": "3420 单"}
]
```

## 5. 前后端数据契约与展现规范

### 5.1 JSON 精度防御（json_value）

JavaScript 环境在解析超过 $2^{53}-1$ 的 64 位大整数时会丢失精度。后端在序列化图表数据时，主动将长整型与 `Decimal` 高精度浮点转换为字符串，日期对象自动转为 ISO 8601 标准字符串。

### 5.2 前端渲染约定

前端在接收到助手消息关联的 `tool_calls` 或证据块时：
- 若包含 `chart` 对象，直接调用前端轻量图表渲染组件（如 ECharts）。
- 坐标轴（`x_key`）、数据系列（`y_keys`）、标题（`title`）完全由契约驱动。
- 移动端根据容器宽度自动调整标签旋转角度（`axisLabel.rotate`）或切换为水平横向柱状图，提供开箱即用的商务级可视化表现。
