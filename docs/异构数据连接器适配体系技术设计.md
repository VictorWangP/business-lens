# 异构数据连接器适配体系技术设计

更新：2026-10-15。本文档说明数据问答系统中的“异构数据连接器（Connectors）适配体系”技术架构、沙箱化资源隔离、驱动协议抽象以及面向本地文件分析（DuckDB / SQLite）和外部企业数仓（PostgreSQL）的特权防范与安全加固机制。

## 1. 架构目标与设计原则

为适应不同的企业数据分析场景，系统需要同时支持两种迥异的数据源形态：
1. **轻量嵌入式本地文件数据集**：业务人员日常上传的 CSV/Excel 表格，经本地物化后由轻量分析引擎执行高并发近实时查询。
2. **企业级外部只读关系数仓**：直连业务方现有的大型 PostgreSQL 生产只读副本或数据仓库。

**核心架构原则**：
- **统一驱动契约（Unified Driver Contract）**：上层 Agent 仅面向统一的 `inspect_source` 与 `execute` 接口，无感知底层底层具体存储方言。
- **主机沙箱隔离与路径防穿越**：本地文件型引擎（DuckDB/SQLite）严禁访问服务器宿主机的文件系统或网络，严格限制内存上限（256MB）与执行超时。
- **数据库特权防范（Principle of Least Privilege）**：对外部 PostgreSQL 连接强制实施“零超级用户、零写权限、强制只读事务、强制客户端超时”四大安全铁律，阻断权限提升与安全侧信道攻击。

## 2. 总体架构与抽象分流

## 3. 本地嵌入式分析引擎安全加固（DuckDB / SQLite）

在 `app/connectors/local.py` 中，针对文件型数据源执行了严密的系统调用隔离：

### 3.1 路径防穿越与所有权保护

数据源密文解密后，提取文件物理绝对路径，并严格校验归属性：
```python
path = Path(value[len(prefix):]).resolve()
root = (settings.USER_STORAGE_DIR / source.user_id / 'data_sources').resolve()
if not path.is_relative_to(root) or not path.is_file():
    raise ValueError('数据集不存在或无权访问')
```
彻底阻断 `../../` 路径穿越读取宿主机 `/etc/passwd` 等敏感系统文件。

### 3.2 DuckDB 嵌入式沙箱参数

通过底层 C++ 配置直接关闭网络与外部文件能力：
- `enable_external_access: 'false'`：禁止在 SQL 中使用 `read_csv()`、`httpfs` 或外部文件加载函数。
- `autoinstall_known_extensions: 'false'` 与 `autoload_known_extensions: 'false'`：阻断第三方外部扩展的动态注入。
- `memory_limit: '256MB'`：设定单次查询内存硬上限，防止复杂笛卡尔积或排序打崩 Worker 内存。
- `threading.Timer(timeout, conn.interrupt)`：后台守护线程强行中断耗时过长的慢查询。

### 3.3 SQLite 防御

- `PRAGMA query_only = ON`：强制将引擎置为纯只读模式。
- `conn.set_progress_handler`：基于单调时钟指令周期的定时熔断，防止正则或无限循环。

## 4. 企业级外部 PostgreSQL 适配与特权防范（app/connectors/postgres.py）

为防范外部配置的数据库连接串具有破坏性权限，系统在建立连接后执行自动化特权审查：

### 4.1 四重安全锁机制

```python
async with conn.begin():
    # 1. 强制会话级只读与超时
    await conn.execute(text('SET TRANSACTION READ ONLY'))
    await conn.execute(text("SELECT set_config('statement_timeout', :v, true)"), {'v': str(settings.SQL_TIMEOUT_MS)})
    await conn.execute(text("SELECT set_config('search_path', 'pg_catalog', true)"))
    
    # 2. 特权角色拦截：禁止超级用户、禁止绕过 RLS 角色、禁止角色创建者
    role = (await conn.execute(text('SELECT rolsuper, rolbypassrls, rolcreaterole, rolcreatedb FROM pg_roles WHERE rolname=current_user'))).one()
    if any(role):
        raise ValueError('业务连接必须使用无超级用户、无绕过 RLS、无创建角色/数据库权限的只读账号')
        
    # 3. 写权限物理扫描：检查当前用户在所有表上的授权
    unsafe = await conn.scalar(text("SELECT EXISTS (SELECT 1 FROM information_schema.table_privileges WHERE grantee=current_user AND privilege_type IN ('INSERT','UPDATE','DELETE','TRUNCATE'))"))
    if unsafe:
        raise ValueError('业务账号具有写入权限，请配置专用只读账号')
        
    # 4. 视图所有权防伪造：禁止读取当前用户自建的可伪造视图，必须读取受控授权视图
    for view in source.allowed_views:
        owner = await conn.scalar(text("""SELECT pg_get_userbyid(c.relowner)=current_user
            FROM pg_class c JOIN pg_namespace n ON c.relnamespace=n.oid
            WHERE n.nspname=:schema AND c.relname=:view AND c.relkind='v' """),
            {'schema': source.schema_name, 'view': view})
        if owner is None or owner:
            raise ValueError('只允许读取非当前账号拥有的授权视图')
```

## 5. 驱动注册中心与接口契约（app/connectors/registry.py）

系统通过轻量工厂模式对外提供统一协议，按需惰性加载底层驱动依赖：

```python
def adapter(source):
    if source.kind in {'duckdb', 'sqlite'}:
        from app.connectors import local
        return local
    if source.kind == 'postgresql':
        from app.connectors import postgres
        return postgres
    raise ValueError('不支持的数据源类型')

async def inspect_source(source) -> list[dict]:
    """自省数据源结构，返回统一格式的:
       [{'table_name': '...', 'column_name': '...', 'data_type': '...'}]"""
    return await adapter(source).inspect_source(source)

async def execute(source, sql: str, params: dict | None = None) -> dict:
    """在目标源上安全执行经过沙箱审计的 SQL，返回结构:
       {'rows': [...], 'truncated': bool, 'sql': str}"""
    return await adapter(source).execute(source, sql, params)
```

## 6. 后续扩展能力规范

当需要新增外部 OLAP 引擎（如 ClickHouse, StarRocks, MySQL, Snowflake）时，只需实现符合上述契约的子模块，并在 `adapter()` 中注册对应 `kind` 映射，无需修改上层 Agent 核心编排流程。
