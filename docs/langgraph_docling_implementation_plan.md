# LangGraph/LangChain + Docling 重构实施计划

日期：2026-10-14　状态：**非 Docling 重构已实现并回归；Docling 验收按用户要求暂停；分支及独立目录均为 rag-langgraph**

## 1. 批准范围与目标

按用户选定方案执行：保留文档解析/索引/检索、关系数据库问数和当前产品功能；Agent 与会话改用 LangGraph/LangChain，解析使用 Docling；移除活动代码、测试、依赖和部署中对 LlamaIndex 的使用。

允许新建数据库及重建数据，不实现旧数据导入、旧 schema 迁移或两代消息协议兼容。新系统采用一套明确的模型与协议。历史设计文档可作为归档记录保留，但不得作为新版启动/实现说明；旧实现只保存在可回退的 Git 基线与独立运行环境中，不在新版保留 legacy 执行分支。

优先复用第三方 runtime、middleware、loader、checkpointer、retriever 和渲染组件；保留必要的授权、SQL 校验、索引版本发布、证据与精确数据业务规则。不新增通用 UI DSL、自定义 Agent 循环或另一套消息流 parser。

## 2. 当前仓库与回退前提

重构开始前的检查结果（历史记录）：

- 项目已有 `.git`，当前分支为 `main`，**没有任何提交**。
- 存在已暂存文件、暂存后又修改的文件，以及尚未跟踪的功能代码和文档。不能仅提交暂存区就宣称保存了现有实现。
- 未配置远程仓库。
- `.env`、`storage/`、venv、node_modules 等已被忽略；它们不随代码提交保存。

上述情况已在 P0 解决：完整基线已提交，保护分支、标签、bundle、数据和私有配置备份已保存，旧环境保持独立。准确位置见末尾实施记录。

### 回退资产清单

| 资产 | 保存方式 | 用途 |
| --- | --- | --- |

## 3. 选定的目标实现

| 层 | 目标 |
| --- | --- |
| Agent | LangChain `create_agent`；确定性校验/澄清/暂停边界使用 LangGraph |
| 上下文 | 原生 SummarizationMiddleware + 明确模型 token 预算 |
| 执行状态 | LangGraph 持久化 checkpointer；单会话单活动执行 |
| 本地存储 | 新应用 SQLite + 独立 checkpoint SQLite；业务快照与知识索引使用隔离的新目录 |
| 文档解析 | Docling + 官方 LangChain loader/HybridChunker 集成 |
| 检索 | LangChain Document/Retriever 与成熟后端适配；保留受权证据边界 |
| SQL | 复用现有连接器与确定性只读 policy，不直接以示例 SQL toolkit 替代 |
| 会话通信 | **主选官方 LangGraph→AG-UI 适配 + assistant-ui AG-UI runtime** |
| UI | 复用 assistant-ui、shadcn、Recharts；按 parts 类型展示 |
| 后台执行 | 保留独立 worker 的调度职责，checkpoint 管理图步骤；SSE 仅订阅 |

通信只实现一个主协议。采用此路线是为了沿用本地 FastAPI/worker 的部署形态，同时复用标准 SDK；不额外自建 LangGraph Agent Server 兼容服务，也不同时引入原生 LangGraph API、AI SDK 与 AG-UI 三套 runtime。

AG-UI 依赖版本、图表/表格顺序、resume 与显式 cancel 必须在 P1 验证。若成熟适配器不能满足且必须维护整套私有聚合器，先提交实际限制及方案调整，不以重新手写 SSE parser 兜底。

## 4. 分阶段实施

### P0：保存并验证旧版基线

1. 清点当前工作区、暂存区和未跟踪文件；纳入现有反馈、认证等完整功能，检查忽略规则和不应入库的数据/凭据。
2. 在短暂停止写入后保存旧 SQLite、文件/索引及私有配置的一致性备份；保留旧依赖环境，随后恢复旧版运行。
3. 将审计后的当前完整源码提交为基线；建立 `baseline/pre-langgraph-20261014` 保护分支和同名基线标签，记录准确 commit SHA。
4. 生成并校验独立 git bundle；输出基线清单和恢复步骤。
5. 从基线隔离检出，验证可以按记录环境启动；运行现有必要检查，记录原有失败项，避免把旧问题误当作新回归。

**门槛：旧版可检出、依赖可恢复、启动可复现，代码与数据备份均有记录。未完成时不得开始重构。**

本地 Git 能满足代码版本回退；若另需异地备份，在获得目标仓库后再同步。普通切分支不能替代被忽略的数据和密钥备份。

### P1：隔离新版环境，验证成熟组件组合

1. 从基线创建 `rag-langgraph` 分支和隔离 checkout；旧版工作区可继续使用。
2. 新建专用 Python 环境、前端安装目录和 `storage-v2/` 数据根；新端口/配置与旧版隔离，所有写入只能进入新版目录。
3. 选择兼容的 LangGraph、LangChain、checkpointer、Docling、AG-UI 与 assistant-ui 版本，锁定完整依赖；核查传递依赖中没有 `llama-index-*`。
4. 用最小流程验证真实工具调用、原生摘要、checkpoint、interrupt/resume、标准事件和官方 UI runtime。
5. 验证首次回答与历史恢复的 parts 顺序、多个工具/图表、网络断连、切换会话及显式停止。

**门槛：能通过官方扩展点实现完整链路，未引入第二套 parser、Agent 循环或消息状态所有者。** 此时不迁移全部产品代码。

### P2：建立新版数据模型与状态所有权

1. 新数据库直接初始化新版 schema；不读取旧数据库做迁移，不保留旧数据兼容代码。
2. 明确三类权威数据：图 checkpoint 保存执行/模型状态；聊天归档保存完整有序展示；结果/资产仓库保存精确查询与原文证据。
3. thread/run 对应用户和业务空间，执行固定授权范围与版本；检查所有读取、取消、恢复和资产访问的所有权。
4. 应用运行记录只承担调度、授权和审计，不重复维护 LangGraph 内部步骤状态；归档与结果使用稳定 ID。
5. 通过 Alembic 管理应用 schema 和必要 checkpointer 初始化；明确生产初始化命令，避免 API 请求期间随意建表。

**门槛：每类状态只有明确写入者，摘要不会删除聊天归档，权限不依赖客户端提供的 thread_id。**

### P3：重构 Agent、工具与后台执行

1. 替换 FunctionAgent、FunctionTool 和 LlamaIndex callbacks，使用 LangChain 模型/工具接口及 middleware。
2. 保留一个 Agent；提供授权 schema/指标、只读 SQL、知识检索和原文读取工具。
3. 使用确定性的 SQL policy、预算与超时；有限纠错、工具错误和调用限制优先使用框架现成能力。
4. 持久化执行使用数据库 checkpointer，暂停使用 interrupt，恢复验证输入并复核权限；明确节点重执行与幂等。
5. worker 只负责有界调度、取消信号和故障后重新调度，图负责已持久化步骤状态；事件断连不停止执行。
6. 用框架结构化输出生成最终答案，保留业务校验和统一 UI 投影；内部 SQL/摘要/格式化流不公开到正文。

**门槛：SQL、文档和联合问题可完成，停止/暂停/恢复/崩溃恢复语义成立。**

### P4：替换文档、索引与检索中的 LlamaIndex

1. 用 Docling 官方 LangChain loader/HybridChunker 替换 TextNode 输出；TXT 使用成熟 splitter 或适合的 Docling 路径。
2. 用 LangChain Document/Retriever 与正式集成替换 BaseRetriever、NodeWithScore、QueryBundle、SentenceSplitter 等引用。
3. 使用成熟 embedding/vector-store/retriever/融合组件替换可替换的通用逻辑，保留必要的授权、来源版本与降级诊断。
4. 保留页面、标题、provenance、原文定位和相邻块读取；禁止框架转换丢失引用信息。
5. 文档入库继续独立于聊天；重建、staged/active 发布、embedding 模型指纹与清理规则适配新版数据。
6. 合并只做类型转换或兼容的旧 facade；直接依赖 `tiktoken` 或所选模型 tokenizer，移除对 LlamaIndex tokenizer 的间接依赖。

**门槛：重新导入文件与业务数据后，检索/引用/更新/删除/重建全部可用，源码和新环境无 LlamaIndex 依赖。**

### P5：统一上下文、会话流与 UI 展示

1. 用原生摘要 middleware 删除固定 12 条/24,000 字符裁剪及拟议的自定义通用摘要 block；保存明确业务参数和结果引用。
2. 配置真实模型窗口、输入/证据/输出预算；工具只给模型必要证据，完整表格/图表数据不重复进入模型历史。
3. 后端采用一个标准事件出口，前端只由官方 runtime 管理 UI 消息；删除双份 SSE 帧解析和通用 applyRunEvent 聚合逻辑。
4. text/image/file/source/tool/data parts 承载内容；表格直接使用结构化查询结果，图表支持多个独立结果。
5. 沿用原生 Composer、Suggestions、复制、语音、滚动及工具 UI；复用 Recharts/shadcn，执行过程默认折叠。
6. 延伸问题、编号标题、显式代码请求和引用均保留业务校验；未知 data part 不回退打印原始 JSON。
7. 不实现旧消息协议兼容；旧代码只从 Git 基线回退，新代码只支持新版结构。

**门槛：新旧页面核心功能一致，多媒体/历史恢复一致，框架承担通用通信与摘要，应用仅保留必要业务适配。**

### P6：完整验收与回退演练

1. 新版测试按目标语义更新，不只是修改断言使测试通过；对当前产品功能执行回归，包含认证、配置、空间、收藏、常问、反馈、语音等。
2. 使用固定文档、SQL 真值和多轮问题集进行真实 provider 验收，覆盖文档+SQL 联合问答与来源正确性。
3. 模拟断网/刷新、切换会话、人工暂停、显式取消、进程中断、重复提交/事件和权限撤销。
4. 检查所有活动源码/测试/依赖/镜像无 LlamaIndex import/package；历史评估文档只作记录。
5. 实际演练：停止新版 → 启动保存的旧 checkout/依赖/数据 → 完成旧版问答；再停止旧版恢复新版。避免两代同时写同一目录。
6. 汇总功能结果、摘要约束保留、回答格式失败、检索质量、响应耗时与资源占用；提供代码删除/新增和剩余自定义职责清单。

**门槛：约定的必测场景全部通过，无阻断性缺陷，真实问答结果可审核，回退演练成功。** 不以“能启动”或少量 mock 测试代替效果验收。

### P7：审核验收结果后完全切换

1. 提交新版验收报告与准确 commit SHA，形成候选版本；测试好后具备完全切换条件，由用户确认验收结果。
2. 合并已验收分支到主线，建立新版发布标签；默认启动/部署配置切到新版数据与环境。
3. 活动主线只保留新方案，删除双实现、旧消息兼容、旧测试替身和无用库；更新 README、架构、启动及重建说明。
4. 旧基线分支/标签/bundle、旧数据和环境按约定保留，不随主线切换删除。

“完全切换”指默认运行和维护都进入新版，不要求立即销毁旧回退资产。

## 5. 必测验收清单

| 类别 | 必测内容 |
| --- | --- |
| SQL | 精确汇总、授权范围、空/截断结果、超时、只读限制、Decimal/大整数 |
| 文档 | PDF/扫描件/表格/TXT、标题页码定位、召回与引用、更新删除和重建 |
| 联合问答 | 数据库数字和文档规定分别引用，不把同时发生解释成因果 |
| 会话 | 多轮、历史归档、模型/空间、编辑重发、三个建议开关与追问 |
| 上下文 | 超过旧窗口的长对话、早期条件与后续纠正、token 预算、工具证据长度 |
| 展示 | 文字、多个图表/表格、图片、复制/语音、默认折叠过程；无原始源码泄漏 |
| 恢复 | 浏览器续看、人工 interrupt/resume、节点故障重执行、明确取消、重复请求去重 |
| 隔离 | 用户/空间/来源版本、resume 再授权、资产读取、新旧目录互不覆盖 |
| 回退 | 基线检出、环境启动、旧数据读取、旧版真实问答、新版再次启动 |

框架不会保证 SQL/摘要/检索天然正确，采用固定问题与证据核查。性能阈值在 P0/P1 取得可复现基线后写入验收表，不预先虚构提升比例。

## 6. 回退步骤

无论切换前还是切换后：

1. 停止新版 API/所有 worker，确认不再写入。
2. 启动保护的旧 checkout 与旧依赖环境；使用保存的私有配置、旧数据根和旧版端口配置。
3. 若旧目录受损，从一致性备份恢复；否则直接使用未被新版改写的旧目录。
4. 检查登录、空间、文档/数据查询和一次真实问答。
5. 保留新版失败现场用于排查，不把新版数据库交给旧版代码。

回退不使用 `git reset --hard` 覆盖未知工作，也不对新数据库执行旧 migration/downgrade。切换后产生的新数据可以按用户授权重建；如需将其带回旧版，需要另行设计，本计划不提供跨代数据迁移。
